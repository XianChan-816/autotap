 一、事故经过与根因
================================================================

【现象】
  安装包含 BackboardProbe 的 v2.0.0-bbprobe1 deb 后，设备直接黑屏。
  强制重启后越狱环境（TrollStore / Dopamine）一并"消失"。

【根因】
  1. BackboardProbe 被注入 backboardd 进程（系统触摸分发的核心进程）。
  2. 代码使用 __attribute__((constructor)) 在进程加载【最早期】执行：
       - dlopen(IOKit)
       - IOHIDEventSystemClientCreate()
       - dispatch_after_f() 排 GCD 定时器
  3. backboardd 是低层 C++ daemon，加载早期 IOKit / GCD main queue
     均未就绪，上述任何一步崩溃都会让 backboardd 进程启动失败。
  4. backboardd 崩 = SpringBoard 依赖的触摸分发不可用 = 整机黑屏。

【等级判定】
  · backboardd / SpringBoard 等系统关键进程注入事故 = 黑屏（最严重）
  · 普通 App 进程注入事故 = 该 App 闪退（可恢复）
  · arm64e PAC 违规（ObjC 元数据） = Safe Mode（可恢复）
  · 编译期错误 = 无 deb，无设备风险

【教训一句话】
  constructor 里只许写文件日志；dlopen / dispatch / API 调用
  一律延迟到进程就绪之后。系统关键进程的早期初始化绝对不能碰。

 二、构建安全检查清单（编译 / 打包层）
================================================================

 在 CI 或本地 make package 阶段就能拦住的问题：

 [ ] 1. ARCHS 必须同时包含 arm64 arm64e
       原因：M1 的 SpringBoard / backboardd 是 arm64e 进程，
             只编 arm64 无法注入；只编 arm64e 在部分进程有兼容问题。

 [ ] 2. 零 ObjC 元数据（项目最高铁律）
       禁止：@implementation / @"..." 字符串字面量 / NSLog /
             block / @selector / __cfstring 常量
       替代：纯 C + 类型化 objc_msgSend + syslog + dispatch_after_f
       原因：arm64e PAC 指针认证下，ObjC 元数据触发崩溃 → Safe Mode。

 [ ] 3. 跨文件 C 符号必须 extern "C"
       原因：Tweak.xm 是 ObjC++（.mm），.c 文件引用的符号会被
             C++ name-mangle → 链接失败（Undefined symbols）。

 [ ] 4. ldid -S 签名（TrollStore / rootless 安装必需）

 [ ] 5. dpkg-deb 的 control 文件禁止 # 注释

 [ ] 6. syslog / printf 字符串里裸 % 必须转义 %%
       原因：-Werror -Wformat-invalid-specifier 直接编译失败。

 [ ] 7. 用到的框架必须在 Makefile 声明（FRAMEWORKS）
       原因：缺框架 → dyld 加载时崩 → 进程起不来（等同黑屏级）。

 [ ] 8. filter 与目标进程匹配
       SpringBoard / App：Filter.Bundles
       backboardd 等 daemon：Filter.Executables
       配错 = 注入失败或注入错进程。

 三、注入进程与加载时机（黑屏 / Safe Mode 高发区）
================================================================

 这一层是本次事故的根源，务必按危险等级处理：

 ┌──────────────────────────────────────────────────────────────┐
 │ 危险等级 1：系统关键进程（backboardd / SpringBoard）           │
 │   后果：黑屏（最严重，几乎无法在设备上自救）                   │
 │   要求：                                                        │
 │   · constructor 内只允许：fopen 写日志 + 简单变量初始化        │
 │   · 严禁：dlopen / dispatch / 任何框架 API / ObjC              │
 │   · 初始化必须延迟：hook 进程就绪后的稳定入口                   │
 │     （如 CFRunLoopRun），首次被调用时再初始化                   │
 │   · 或改用独立 daemon 进程注入（见下）                          │
 └──────────────────────────────────────────────────────────────┘
 ┌──────────────────────────────────────────────────────────────┐
 │ 危险等级 2：普通 App 进程                                     │
 │   后果：该 App 闪退（可恢复，重新打开即可）                     │
 │   要求：constructor 可做轻量初始化，但 dlopen / GCD 仍建议延迟 │
 └──────────────────────────────────────────────────────────────┘
 ┌──────────────────────────────────────────────────────────────┐
 │ 危险等级 3：独立 daemon 进程（launchd 拉起）                   │
 │   后果：daemon 崩 = 只有它自己退出，绝不影响系统               │
 │   推荐：新实验/新注入方案优先用 daemon 验证                    │
 │   例：IOHID 注入可放 daemon 内做，验证"不顶掉"假设            │
 └──────────────────────────────────────────────────────────────┘

 关键认知：
 · backboardd 不是 UIKit 进程（C++ daemon），不能套用 UIKit 假设；
   CF / GCD 初始化时机不确定，constructor 阶段风险最高。
 · 独立 daemon 验证是"安全试错"的最佳路径：
   假设错了顶多 daemon 退出，不会把设备带崩。

 四、运行时编码铁律（arm64e PAC）
================================================================

 除编译期零 ObjC 元数据外，运行时代码还要注意：

 [ ] 遍历触摸：allTouches 是 NSSet，必须先 allObjects 转数组
     再用 objectAtIndex:（直接对 NSSet 用 objectAtIndex: = Safe Mode）
     诊断场景用 anyObject。

 [ ] 事件构造签名不可改：
     · IOHIDEventCreateDigitizerEvent = 15 参数（含 buttonMask）
     · IOHIDEventCreateDigitizerFingerEvent = 13 参数
     · 多参/少参 → 事件畸形 → 系统忽略或行为异常。

 [ ] 父事件字段（权威值）：
     · type=3（Hand）、index=99（避免与真实 hand 冲突）
     · DisplayIntegrated = 0x0B0017 = 1（0x0B0005 是错的）
     · child down mask = 0x03；UP 父事件 Range/Touch 必须 = 0

 [ ] up-delay 必须大于连点间隔（铁律）：
     间隔 40ms → up-delay 45ms（down(N+1) 晚于 up(N) 5ms）。
     up-delay 小于等于间隔 → 系统判冲突 → 顶掉 → 连点断续。

 [ ] 注入必先 FT_HIDConnect()（幂等）：
     探测 / 派发入口必须自保证 client 已建立，否则静默丢弃。

 [ ] 日志先行：所有新代码先写 /tmp/*.log 确认 ctor 执行、
     初始化成功，再继续后续逻辑——黑屏事故 30 秒可定位。

 五、发布与验证流程（防事故扩散）
================================================================

 [ ] 1. 新实验组件独立 deb 打包
       绝不与稳定版混装。装坏只卸实验件，不动主功能。
       （本次事故就是把 BackboardProbe 与 FloatingTap 打在一起）

 [ ] 2. 新 deb 先验证"可干净卸载"
       plist 规范 + 安装路径可被 Sileo/Filza 移除，才有后悔药。

 [ ] 3. 安装后先看 ctor 日志
       /tmp/*.log 第一行确认：dylib 加载成功、constructor 跑完。

 [ ] 4. 分级验证：
       先验"不崩"（日志正常）→ 再验"功能"（注入送达）→
       最后验"不顶掉"（手指按住 5 秒不中断）。

 [ ] 5. 保留恢复通道
       明确知道：如何卸载、如何进安全模式、如何重装环境。

 [ ] 6. 版本号清晰标记实验版
       如 2.0.0-bbprobe1，避免与稳定版 1.0.x 混淆。

 六、越狱环境恢复知识（Dopamine / TrollStore）
================================================================

 【Dopamine 是半绑定越狱】
   强制重启后 /var/jb（rootless 文件系统）未挂载 → tweak 不加载、
   悬浮球消失。这不是损坏，重新激活即可。

 【"巨魔消失"的真相】
   TrollStore 及其签名 App（Dopamine / Filza 等）装在 /var/jb 内，
   未激活时不可见 → 系统提示"非 App Store 下载 / 未安装巨魔"。
   这是 /var/jb 未挂载的表现，不是真的被卸载。

 【恢复步骤】
   1. 电脑爱思助手装 GTA Car Tracker（iOS 15.5 的 TrollStore 安装器）
   2. 手机打开 → Install TrollStore
   3. TrollStore 装 Dopamine.ipa（如已丢失）
   4. 打开 Dopamine → 点"越狱/激活" → 自动重启 → /var/jb 恢复

 【安全模式】
   Dopamine 安全模式 = 开机时按住音量减（不加载第三方 tweak），
   用于抢救"加载 tweak 就黑屏"的状态。

 【预防死锁】
   如果某 tweak 会导致黑屏，先想办法在激活前删除它的 dylib
   （安全模式 / 独立文件管理器），再重新激活。
